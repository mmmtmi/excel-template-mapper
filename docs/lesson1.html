Lesson 1

サーバーを起動する

この回は起動そのものより、起動時に何が初期化されるかを把握することが目的です。

この回のゴール

  • MySQL と API サーバーを起動できる
  • cmd/api/main.go が何を初期化しているか説明できる
  • GraphQL Playground に到達する HTTP 経路を説明できる

実行手順

docker compose up -d
docker compose exec -T mysql mysql -uapp -papp excel_template_mapper < db/migrations/001_init.up.sql
go run cmd/api/main.go

ブラウザでは http://localhost:8080 を開きます。

起動確認

docker compose ps
docker compose exec mysql mysql -uapp -papp excel_template_mapper -e "SHOW TABLES;"
  • mysql が Up なら DB 起動成功
  • mapping_templates と mapping_rules が見えれば migration 成功

読むファイル

  1. cmd/api/main.go
  2. internal/dbconn/dbconn.go
  3. graph/resolver.go

読むポイント

  • LoadMySQLConfigFromEnv(".env"): どの env を読むか
  • dbconn.Open: DB 接続の確立
  • service.NewProcessor: どこで service を組み立てるか
  • graph.NewExecutableSchema: gqlgen の schema をどこで生成するか
  • playground.Handler と /query: ブラウザ画面と API エンドポイントの対応

考える問い

  1. なぜ main.go は SQL を直接書かず、repository と processor を組み立てるだけなのか
  2. なぜ GraphQL Playground の URL と実際の Query URL が分かれているのか
  3. なぜ DB 接続は起動時に 1 回だけ作る設計が多いのか

確認用メモ

この回が終わった時点で、次の説明ができれば十分です。

main.go
  -> .env を読む
  -> DB 接続を作る
  -> repository を作る
  -> processor を作る
  -> resolver に渡す
  -> GraphQL handler を起動する
