Lesson 3

Resolver を読む

この回では schema で宣言したフィールドが、どの Go 関数で実装されているかを追います。

この回のゴール

  • Resolver の役割を説明できる
  • 入力バリデーション、service 呼び出し、レスポンス整形の境界を説明できる
  • Mutation 実装の読み方を身につける

読むファイル

  1. graph/schema.resolvers.go
  2. graph/resolver.go
  3. graph/generated.go

重点的に読む関数

  • CreateTemplate
  • UpdateTemplate
  • CreateRule
  • ProcessExcel
  • ProcessExcelOnly

Resolver の責務

GraphQL input
  -> 必須値チェック
  -> 必要なら Upload を一時ファイルへ保存
  -> service / repository を呼ぶ
  -> GraphQL の型へ詰め直して返す

ここに「変換ロジックそのもの」を書き込みすぎると、resolver が肥大化します。

具体的に見る観点

  1. なぜ strings.TrimSpace によるバリデーションを resolver で行っているか
  2. なぜ uuid.NewString() を resolver 側で採番しているか
  3. なぜ Upload をそのまま service に渡さず、一時ファイルへ保存しているか
  4. なぜ GraphQL の model と internal model が分かれているか
