Lesson 9

改善案を提案し、実装する

この回は最終課題です。改善案を Markdown にまとめ、PR 形式で提案し、実際に 1 つ選んで実装まで進みます。

この回のゴール

  • 改善案を第三者がレビューしやすい形で説明できる
  • 1 つの改善を実装計画へ落とせる
  • 可能なら実装、テスト、確認まで完了できる

ステップ 1: 提案書を作る

Lesson 8 で作った案の中から、優先度が高く、効果が説明しやすいものを 1 つ選びます。

提案書は Markdown で作成します。たとえば docs/proposals/add-trim-upper.md のような場所に置きます。

例:
- transform を増やしやすい構造へ変更する
- processExcel の返り値を GraphQL 的に自然な型へ変える
- CELL sourceType を最低限サポートする

ステップ 2: PR 用の説明を書く

提案書ができたら、次はその内容をそのまま PR 説明へ流用できる形に整えます。

1. この PR で解決したい問題
2. 変更内容
3. 影響範囲
4. 確認方法
5. 未対応の課題

ステップ 3: 実装計画を書く

1. どのファイルを変えるか
2. 追加するテストは何か
3. 既存挙動への影響は何か
4. どう確認するか

ステップ 4: 実装する

  • まず小さく変更する
  • git diff で差分を確認する
  • go test ./... で回帰がないか確認する

ステップ 5: 実装後レビュー

  1. 変更前より何が良くなったか
  2. まだ残っている課題は何か
  3. 次に着手するなら何か

提出イメージ

  • docs/proposals/xxx.md: 改善提案書
  • コード差分: 実際の実装
  • PR 説明: 提案書を要約して記載

この形にすると、レビュー側は「提案」と「実装」を分けて確認できます。

この教材の最終到達点

コードを読めるだけでなく、改善余地を見つけ、提案書に整理し、レビュー可能な形で実装まで進めるところまで到達することがこの教材の最終目標です。
