Lesson 2

GraphQL とは何か

この回は GraphQL の概念を先に整理し、その後でこのリポジトリの schema を読みます。

この回のゴール

  • GraphQL が何を解決したい技術か説明できる
  • REST と GraphQL の違いを説明できる
  • このリポジトリの schema を読める

解説 1: GraphQL とは

GraphQL は API のためのクエリ言語であり、同時にその API がどんなデータを返せるかを定義する型システムです。

REST では「URL ごとに固定のレスポンス」が返ることが多いですが、GraphQL ではクライアントが「欲しい項目だけ」を指定できます。

クライアント
  -> 欲しいフィールドを宣言する
  -> サーバーはその形に合わせて返す

解説 2: REST との違い

  • REST: エンドポイント単位で設計することが多い
  • GraphQL: データの型とフィールド単位で設計する
  • REST: 複数リソース取得で複数回リクエストになりやすい
  • GraphQL: 1 回の Query にまとめやすい
  • REST: サーバー側が返り値の形をかなり固定する
  • GraphQL: クライアントが取得形をある程度選べる

読む 1: schema を開く

  1. graph/schema.graphqls を開く
  2. scalar Upload を探す
  3. type Query と type Mutation を探す
  4. Template と Rule を探す

ここでは「この API は何を返せるか」「何を受け取れるか」を読む意識で見ます。

解説 3: schema の読み方

  • String!: 必須の文字列
  • String: null を許す文字列
  • [Template!]!: null でない配列で、要素も null ではない
  • input: クライアントから受け取る専用型
  • type: サーバーが返す型

この型定義があることで、GraphQL はドキュメントでもあり、バリデーションの土台にもなります。

読む 2: 実際に Query と Mutation を打つ

query {
  templates {
    id
    name
    target
    headerRow
    dataStartRow
  }
}
mutation {
  createTemplate(input: {
    name: "deep_dive_template"
    headerRow: 1
    dataStartRow: 2
  }) {
    id
    name
    target
  }
}

実行したあとで、「返ってきた JSON の形が schema と一致しているか」を確認します。

解説 4: gqlgen の役割

このプロジェクトは schema first です。先に schema.graphqls を定義し、その schema から gqlgen が Go の型や resolver interface を生成します。

go run github.com/99designs/gqlgen generate

生成物の中心は graph/generated.go と graph/model/models_gen.go です。普段の編集対象は schema と resolver 実装です。

読む 3: 生成物を確認する

  1. graph/generated.go を開く
  2. type QueryResolver を探す
  3. type MutationResolver を探す
  4. graph/model/models_gen.go を開き、GraphQL 型に対応する Go 構造体を確認する

整理

schema.graphqls
  -> API の仕様
  -> gqlgen generate
  -> generated.go / models_gen.go
  -> schema.resolvers.go で実装する
