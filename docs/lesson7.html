Lesson 7

GraphQL で一連の流れを再現する

この回では schema、resolver、repository、processor の理解をつないで、実際に 1 本の変換フローを通します。

この回のゴール

  • Template を作成できる
  • Rule を追加できる
  • Excel 変換 Mutation の位置づけを理解できる

手順 1: Template を作る

mutation {
  createTemplate(input: {
    name: "report_v1"
    headerRow: 1
    dataStartRow: 2
  }) {
    id
    name
  }
}

手順 2: templateId を取得する

query {
  templates {
    id
    name
  }
}

手順 3: Rule を作る

mutation {
  createRule(input: {
    templateId: "取得した templateId"
    sourceKey: "カスタマID"
    sourceType: "HEADER"
    targetLabel: "顧客ID"
    required: true
  }) {
    id
    sourceKey
    targetLabel
  }
}

手順 4: 状態を確認する

query {
  rules(templateId: "取得した templateId") {
    sourceType
    sourceKey
    targetLabel
    required
  }
}

ここで理解すべきこと

  • Template は読み取り方法を定義する
  • Rule は列と出力キーの対応を定義する
  • Processor は両方を受けて Excel を JSON に変換する

考える問い

  1. なぜ Template と Rule を別テーブルにしているのか
  2. Rule に priority があるのはどんな将来要件を見越しているのか
  3. Mutation で一括登録 API を用意したくなったら、どこが複雑になるか
